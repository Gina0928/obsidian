## 1. 涉及的表与关键列

### md_sku（集团商品主数据，用于映射）
| 列 | 类型 | 说明 |
|---|---|---|
| id | bigint | **组内 sku 主键** |
| source_sku_id | varchar(50) | 外部商品编码（业务侧给的 822931/808424/670923 等） |
| sku_name / full_name | varchar | 名称（注意：808423/808424/822931 的 sku_name 为「作废」） |

### pos_do_detail（挂单明细，修复主表）
| 列 | 类型 | 说明 |
|---|---|---|
| id | bigint PRI | 主键 |
| do_h_id | bigint | 挂单头 id |
| source_sku_id | varchar(50) | 外部商品编码（查小数行用此列） |
| qty | decimal(10,3) | 计件数量（待修复列） |
| wh_id | bigint | 门店 |
| del_flag | tinyint | 0=有效 |

⚠️ **pos_do_detail 没有 `sku_id` 列**，挂单侧一律用 `source_sku_id`。

### asn_detail（收货单明细，排查「挂单导致收货异常」）
| 列 | 类型 | 说明 |
|---|---|---|
| id | bigint PRI | 主键 |
| asn_header_id | bigint | 收货单头 id |
| sku_id | bigint | **存的是 md_sku.id（组内主键），不是 source_sku_id** |
| expt_qty | decimal(14,3) | 预期收货数量（待排查列） |
| wh_id | bigint | 门店 |
| line_status | varchar(2) | 行状态 |
| del_flag | tinyint | 0=有效 |

⚠️ **id 空间陷阱**：业务给的 808423 / 671447 是 `source_sku_id`，但 `asn_detail.sku_id` 存的是 `md_sku.id`。映射：
- source_sku_id `671447` → md_sku.id `55628`
- source_sku_id `808423` → md_sku.id `72024`

直接 `sku_id in (808423, 671447)` 会返回 0 行（错配）。必须先做 source_sku_id → md_sku.id 映射。

## 4. 整除核对口径

对每条小数行 `qty`，设系数为 `c`：
- **整除**：存在整数 `n` 使 `qty = c × n`（残差 ≤ 1e-4）。例：`1.100 / 1.1 = 1`、`2.200 / 1.1 = 2` 通过；`1.500 / 1.1 = 1.3636…` 不通过。
- **已整数**：`FLOOR(qty) == qty`。说明已修复或示例过时，**不得再除系数**（否则 1.000 → 0.909 破坏数据）。
- 不通过 / 已整数 / 缺系数 → 一律不进 UPDATE，列入人工复核。
