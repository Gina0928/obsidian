# 企业微信交付规范（结论优先，禁止思考过程）

本技能在企业微信（WeCom）通道下以「远程任务」方式被触发：用户发消息 → 助理执行
排查 → 最终把结果经企业微信回传（如交付胡雨）。**企业微信里用户只能看到最终那一条
回复，看不到中间的思考、试错、工具调用与文档阅读过程**。因此最终消息必须是一份自洽
的「结论稿」，而不是工作笔记。

> **使用时机**：凡结果要经企业微信回传，一律先读本文件再写最终回复。
> 用户在会话里直接交互时，按 SKILL.md「输出规范」正常展开，不套用本规范。

## 最终回复的三段式结构（移动端友好）

1. **一句话结论 / 判断**（最前面，让用户 3 秒内读懂结果，红/绿按结论性质即可）。
2. **关键证据**（精简结构化表格，仅放能直接支撑结论的字段；金额与数量保留 Decimal
   精度，不四舍五入；口径有歧义时加一行注）。
3. **数据来源与口径**（门店 wh_id、时间区间、来源库、是否含日志交叉）+ 可选的
   **下一步建议**（一句，给可执行动作）。

## 禁止带入企业微信最终回复的内容

- 思考过程 / 推理链条（"我怀疑是 X，于是去查 Y" 这类叙述）。
- SQL 原文堆砌、返回行数、`EXPLAIN` 片段、工具调用清单、`curl` URL。
- 文档阅读过程（"先读了 finishCount 优化文档……"）——结论里只保留文档支撑的要点。
- 中途试错、空查询、重试记录、`已定位门店：xxx` 这类内部状态回显。
- `traceId` 完整链路 / 异常堆栈全文（除非它是结论本身的核心证据，且已精简为要点）。
- 用于自我对齐的计划段落（如"本次计划：先 A 再 B"）。
- 源码拉取、git 命令、仓库路径等取证过程（结论里只保留「代码层面定位到 X 类 Y 方法」）。

## 未定位到根因时怎么回

直接写结论：「未定位到确定根因，已排除 A / B / C（各一句话）」，并给建议的下一步
（如"建议补充 traceId 或业务发生时间后复查"）。**不要发一长篇"我做了什么但没找到"**。

## 触发判定

- 用户在**本会话直接交互**（能看到工具过程）时，按输出规范正常展开。
- 凡结果要经**企业微信回传**（远程任务），一律套用本规范收敛为结论稿，无论排查
  过程多长、查了多少库。
